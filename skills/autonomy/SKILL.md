# Autonomy

Use this skill when Zach gives a bounded unattended window. Treat the window as execution authority for routine local work only; retain Zach approval for destructive, financial, account, privacy/security, credential, irreversible, deployment/push, message-sending, and live-trade actions.

## Preflight

1. Parse the exact return time or duration, timezone, current time, named outcome, exclusions, and interruption signal. Convert relative language into one explicit wall-clock deadline; if it is ambiguous or already past, resolve that before execution.
2. Read the active goal, relevant instructions, repository state, dirty-checkout status, active workers, and current task artifacts. Preserve unrelated changes and never share an editing checkout.
3. Resolve every real permission, credential, sensitive-action boundary, product fork, missing input, and external dependency before Zach leaves. Batch questions and end the question set with "anything else to add?". Block only the dependent or sensitive lane while a required decision remains open; continue unrelated work that is already authorized and safe.
4. Create or continue one durable goal whose end condition is the observed acceptance criteria. Maintain an obligation ledger with owner, exact model, effort/mode, folder/worktree, dependencies, acceptance, next check, and evidence; put unfinished obligations on the active board.
5. Compose modes without duplicating control: `$autonomy` owns the deadline, permission envelope, interruption, and unattended lifecycle; a paired `$build-sprint` owns critical-path scope and prioritization; a paired `$overnight` owns the evening planning/morning-closure framing.

## Execute

1. If paired, invoke `$build-sprint` after autonomy preflight, then invoke `$delegate` for the resulting multi-lane plan. Otherwise invoke `$delegate` directly when its trigger applies. Dispatch independent lanes early with complete packets and isolated folders/worktrees. State the exact model, effort/mode, and folder for every lane; use current roster verification rather than stale routing.
2. Finish research and engineering before polish. Keep the opened session as owner and final gate; monitor every worker through terminal success, failure, waiting, or cancellation. Inspect diffs and artifacts, not "sent," "dispatched," "build passed," or "saved to memory" labels.
3. Recover failures within scope, reprompt drift, and reroute only with a recorded reason. When engineering/research reaches a candidate result, move immediately into actual-product verification instead of idling.
4. Stop promptly when Zach interrupts. Reserve enough time before the wall-clock deadline for shutdown and reconciliation. At the deadline, start no new work and transition every dispatched lane to terminal success, failure, waiting, or cancellation; interrupt/cancel any worker still executing after preserving its recoverable artifacts and next trigger. Do not publish the final Read-Me while a worker is running, and do not silently extend the work window as a monitoring grace period.

## Verify the real result

1. Run relevant automated checks, inspect the final diff, and perform an adversarial review.
2. Invoke `$codexaudit` for changed user-facing work. Launch the actual app or workflow, use live computer control, and exercise the changed path plus adjacent flows. Prefer Microsoft Edge for visible browser QA.
3. Repair confirmed in-scope defects, rerun checks, and repeat the live audit until acceptance passes or a genuine Zach decision, sensitive permission, or external blocker remains.
4. Reconcile every obligation against the goal and board before reporting. Report exact paths, worker evidence, checks, live observations, and unresolved blockers. Never equate elapsed time, a worker response, or a green build with completion.

## Safety and stop conditions

Before unattended execution, obtain explicit approval for any sensitive action. Do not expose secrets or move them. Do not place trades, send messages, push or deploy, change accounts, or make irreversible changes. If the app cannot run after safe recovery, preserve concrete blocker evidence and stop at the window boundary.
